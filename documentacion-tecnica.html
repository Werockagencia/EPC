3. Estructura del tema

wp-content/themes/epc-cajica/
├─ functions.php          carga de módulos
├─ theme.json             paleta, tipografías y ajustes de bloques
├─ templates/ parts/      plantillas de bloques, encabezado y pie de página
├─ page-templates/        plantillas del panel del ciudadano (panel-*.php, login, PQRS…)
├─ assets/ css/ js/ images/   estilos, scripts (site.js, header.js, panel.js) e imágenes
└─ inc/
   ├─ paginas/*.php       campos editables por página (textos, fotos, listas)
   ├─ *-render.php        pintan cada página a partir de esos campos
   ├─ transparencia-*.php 13 numerales, 22 subpáginas y listas de documentos
   ├─ roles.php, auth.php, cuentas.php, validacion-propietario.php   roles y portal
   ├─ pqrs-tramites.php, comercial-panel.php, encuesta.php           PQRS, trámites, panel Comercial
   ├─ pwa.php             manifest y service worker
   └─ migraciones.php     cambios de contenido de una sola vez, automáticos al desplegar

Los archivos subidos (documentos, fotos, videos de lengua de señas) viven en wp-content/uploads/; los 513 documentos de Transparencia están en uploads/transparencia/.

4. Contenido editable

Cada página tiene un panel "Contenido editable" en su pantalla de edición (Páginas → editar). Allí se cambian textos, fotos, cifras y listas sin tocar código. Tipos de campo: texto, texto largo, imagen, HTML, repetidor (listas de tarjetas, preguntas, integrantes) y lista de documentos (Título | enlace, ## Subtítulo para grupos). Si un campo se deja vacío o nunca se guardó, se muestra el valor por defecto definido en inc/paginas/<página>.php.

8. Despliegue

  1. Probar el cambio en local (http://localhost:8890) y revisar enlaces.
  2. Empaquetar solo los archivos cambiados en un .zip (generado con PHP ZipArchive, no con el compresor de Windows) respetando las rutas del tema.
  3. hPanel → Archivos → Administrador de archivos → subir el zip a public_html/wp-content/themes/epc-cajica/ → clic derecho → Extract (carpeta "."; marcar sobrescribir) → borrar el zip.
  4. hPanel → Tablero → Limpiar caché.
  5. Abrir cualquier página una vez: inc/migraciones.php aplica los cambios de contenido pendientes (se registran en opciones de WordPress y no se repiten).
  6. Verificar: páginas principales con respuesta 200 y revisión de enlaces rotos.
Evitar subir muchos archivos sueltos por FTP: el hosting bloquea la IP por ráfagas de conexiones. Para archivos grandes (documentos), usar un zip o un script temporal protegido que se borra solo.

9. Respaldo y recuperación

Copias existentes

  • Hosting: copias automáticas diarias de archivos y base de datos (última verificada: 14 de octubre de 2026) y copias manuales cada 24 horas desde hPanel → Archivos → Copias de seguridad.
  • Código: el tema está versionado en GitHub (Werockagencia/epc-cajica-theme).
  • Contenido y documentos: insumos organizados en el repositorio del proyecto (diagnóstico, requerimientos, fotos, documentos y paquetes de despliegue).

Antes de un cambio importante

hPanel → Copias de seguridad → Crear respaldo (manual) y esperar a que figure como completado.

Procedimiento de recuperación

  1. Fallo del tema o de una actualización: restaurar solo archivos desde hPanel → Copias de seguridad → "Restaurar y descargar" → archivos (carpeta wp-content/themes/epc-cajica), o volver a extraer el último zip de despliegue.
  2. Fallo de contenido: restaurar la base de datos desde la misma pantalla eligiendo la fecha anterior al incidente.
  3. Sitio caído por completo: restaurar la copia completa (archivos y base de datos) más reciente y limpiar caché.
  4. Verificar: inicio, Transparencia, login, una PQRS de prueba y el asistente en WhatsApp.
Objetivos: incidentes críticos atendidos en 4 horas hábiles, con solución o plan de contingencia en las 24 horas siguientes (contrato). Restauración desde copia diaria: pérdida máxima de 24 horas de cambios.
Pendiente: realizar una restauración de prueba en staging y dejar registro de fecha y resultado.

10. Seguridad y accesos

  • SSL activo; contraseñas gestionadas por WordPress (hash); acceso al panel solo con sesión y por rol; PQRS anónima con anonimato forzado.
  • El panel Comercial no da acceso a wp-admin; el administrador es el único rol que gestiona páginas, tema, plugins y usuarios del sitio.
  • Recomendado antes de salir al aire: contraseñas largas únicas para administradores, segundo factor de autenticación y revisar la lista de administradores.
